## Документация для проекта "Домен" (Domain)

Данная документация описывает предметную область (домен) проекта, включая сущности, атрибуты, связи и бизнес-правила.

### 1. Обзор предметной области

Проект "Учет расходов" предназначен для управления личными финансами, позволяя пользователям регистрировать свои расходы, классифицировать их по категориям и анализировать свои траты за определенные периоды времени.

### 2. Сущности и их атрибуты

#### 2.1. Кошелек (Wallet)

* **Id** (int): Уникальный идентификатор кошелька.
* **Name** (string): Название кошелька (обязательное поле).

#### 2.2. Автор (Author)

* **Id** (int): Уникальный идентификатор автора.
* **Name** (string): Имя автора (обязательное поле).

#### 2.3. Категория (Category)

* **Id** (int): Уникальный идентификатор категории.
* **Name** (string): Название категории (обязательное поле).
* **Author** (Author): Автор категории (обязательное поле).
* **Color** (Color?): Цвет, связанный с категорией (необязательное поле).

#### 2.4. Расход (Expense)

* **Id** (int): Уникальный идентификатор расхода.
* **Amount** (Money): Сумма расхода (обязательное поле).
* **TransactionDate** (DateTime): Дата и время совершения расхода (обязательное поле).
* **Description** (string?): Описание расхода (необязательное поле).
* **Author** (Author): Автор расхода (обязательное поле).
* **Wallet** (Wallet): Кошелек, с которого был произведен расход (обязательное поле).
* **Category** (Category): Категория расхода (обязательное поле).

#### 2.5. Деньги (Money) - Value Object

* **Value** (decimal): Числовое значение суммы.
* **Currency** (string): Код валюты (например, "USD", "EUR", "RUB").

### 3. Связи между сущностями

* **Кошелек \*--1 Расход**: Один кошелек может иметь много расходов.
* **Автор 1--\* Категория**: Один автор может создавать много категорий.
* **Автор 1--\* Расход**: Один автор может совершать много расходов.
* **Категория 1--\* Расход**: Одна категория может быть связана со многими расходами.

### 4. Бизнес-правила

* Сумма расхода должна быть больше нуля.
* Название кошелька, автора и категории не может быть пустым.
* Дата транзакции расхода не может быть будущей датой.
* Валюта расходов должна быть корректной (например, соответствовать стандарту ISO 4217).

### 5. Контекст предметной области

Предметная область "Учет расходов" ограничена функциональностью учета и анализа личных финансов.

### 7. Value Object

`Money` является Value Object, что означает, что его идентичность определяется его свойствами (`Value` и `Currency`), а не уникальным идентификатором. Value Object являются неизменяемыми.

### 8. Сервисы предметной области

Для выполнения сложных расчетов, таких как расчет общей суммы расходов за период или средней суммы расходов, в доменном слое определены сервисы (например, `IExpenseCalculationService`).

### 9. Репозитории

Для доступа к данным предметной области используются репозитории (например, `IExpenseRepository`, `IWalletRepository`, `ICategoryRepository`, `IAuthorRepository`). Репозитории предоставляют интерфейс для работы с коллекциями сущностей и скрывают детали реализации хранения данных.

### 10. Фабрики

Для создания сложных объектов предметной области используются фабрики (например, `IExpenseFactory`, `ICategoryFactory`). Фабрики инкапсулируют логику создания объектов и обеспечивают консистентность данных.

Данная документация предоставляет общее представление о предметной области проекта "Учет расходов". Она может быть дополнена и уточнена в процессе разработки.
