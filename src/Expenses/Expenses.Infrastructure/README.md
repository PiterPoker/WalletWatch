# Expenses.Infrastructure

Этот слой инфраструктуры предоставляет реализацию доступа к данным для приложения управления расходами.

Конечно, давайте подробнее опишем классы, представленные на скриншоте, и их роли в слое инфраструктуры вашего приложения.

**1. Configurations (Конфигурации):**

* **Назначение:**
    * Эти классы используются для настройки Entity Framework Core (EF Core) и определения того, как ваши сущности (Author, Category, Expense, Wallet) будут сопоставляться с таблицами базы данных.
    * Они позволяют вам задавать ограничения, связи, типы данных и другие параметры, необходимые для корректного взаимодействия EF Core с вашей базой данных.
* **Классы:**
    * **AuthorConfiguration.cs:**
        * Настраивает маппинг сущности `Author` на таблицу `Authors`.
        * Определяет свойства, ограничения и связи, специфичные для сущности `Author`.
    * **CategoryConfiguration.cs:**
        * Настраивает маппинг сущности `Category` на таблицу `Categories`.
        * Определяет свойства, ограничения и связи, специфичные для сущности `Category`.
    * **ExpenseConfiguration.cs:**
        * Настраивает маппинг сущности `Expense` на таблицу `Expenses`.
        * Определяет свойства, ограничения и связи, специфичные для сущности `Expense`.
    * **WalletConfiguration.cs:**
        * Настраивает маппинг сущности `Wallet` на таблицу `Wallets`.
        * Определяет свойства, ограничения и связи, специфичные для сущности `Wallet`.
* **Важность:**
    * Эти классы обеспечивают гибкость и контроль над тем, как EF Core взаимодействует с вашей базой данных.
    * Они позволяют вам настраивать маппинг сущностей в соответствии с требованиями вашего приложения.

**2. Repositories (Репозитории):**

* **Назначение:**
    * Эти классы реализуют паттерн "Репозиторий", предоставляя интерфейс для доступа к данным.
    * Они инкапсулируют логику доступа к данным, скрывая детали реализации EF Core от остальной части приложения.
    * Они обеспечивают отделение доменной логики от логики доступа к данным.
* **Классы:**
    * **AuthorRepository.cs:**
        * Реализует интерфейс `IAuthorRepository`.
        * Предоставляет методы для выполнения операций CRUD (Create, Read, Update, Delete) с сущностью `Author`.
    * **CategoryRepository.cs:**
        * Реализует интерфейс `ICategoryRepository`.
        * Предоставляет методы для выполнения операций CRUD с сущностью `Category`.
    * **ExpenseRepository.cs:**
        * Реализует интерфейс `IExpenseRepository`.
        * Предоставляет методы для выполнения операций CRUD с сущностью `Expense`.
    * **WalletRepository.cs:**
        * Реализует интерфейс `IWalletRepository`.
        * Предоставляет методы для выполнения операций CRUD с сущностью `Wallet`.
* **Важность:**
    * Эти классы упрощают доступ к данным и делают ваш код более тестируемым и поддерживаемым.
    * Они позволяют вам легко заменять реализацию доступа к данным без изменения остальной части приложения.

**3. ExpensesContext.cs:**

* **Назначение:**
    * Этот класс является вашим `DbContext` (контекстом базы данных) для EF Core.
    * Он представляет собой сессию с базой данных и используется для выполнения запросов и сохранения изменений.
    * Он знает о ваших сущностях и их отношениях.
* **Функциональность:**
    * Предоставляет свойства `DbSet` для доступа к таблицам базы данных.
    * Использует конфигурации (из папки `Configurations`) для настройки маппинга сущностей.
    * Реализует интерфейс `IUnitOfWork` для управления транзакциями.
* **Важность:**
    * Этот класс является центральным компонентом вашего слоя инфраструктуры, обеспечивая взаимодействие с базой данных.

**Общая Роль Слоя Инфраструктуры:**

* Слой инфраструктуры отвечает за предоставление доступа к данным и другим внешним ресурсам.
* Он обеспечивает отделение доменной логики от деталей реализации доступа к данным.
* Он делает ваш код более тестируемым, поддерживаемым и гибким.
